# health-fhir-validation

Layer: **contracts**. FHIR R5 validation (ADR 0016; fhir-r5-model.md § Validation, § Tier 1 in code). Pure: no I/O, no model crate.

- **`validate_structure(json)` and `validate_value(&value)`** run tier 1 on raw JSON (ADR 0051). They report:
  - an unknown or abstract `resourceType`;
  - unknown elements;
  - cardinality and required elements;
  - primitive JSON types, regexes and integer ranges;
  - choice exclusivity;
  - empty objects, arrays and strings;
  - `null` and `_name` alignment.

  Each `Issue` has an OperationOutcome code and a FHIRPath location.
- **`data/r5-elements.json`** is generated by `tools/fhir-element-table` from `hl7.fhir.r5.core#5.0.0`. Never edit it by hand. `tools/fhir/check-element-table.sh` checks it for drift, and `--write` regenerates it.
- **`validate_invariants(&engine, &value)`** runs tier 2: the R5 core invariants (severity error) evaluated by path with a `FhirPathEngine` (fhir-r5-model.md § Tier 2 in code). `KNOWN_ENGINE_GAPS` lists the invariants it skips, with reasons. `HOLDS_BY_SHAPE` skips the hot invariants on a node whose shape proves they hold, such as `dom-2`–`dom-5` without `contained`, or `ref-1` on a reference that is not local.
- **`OctofhirEngine`** is the default `FhirPathEngine`: the vendored, patched `octofhir-fhirpath` (third_party/, ADR 0052) over `TableModelProvider`. It runs in its own task, so a panic fails closed, and it discards `trace()` output.
- **`ProfileSet::compile(&definitions)`** compiles StructureDefinition snapshots for tier 3 (ADR 0053; fhir-r5-model.md § Tier 3 in code). It refuses a differential-only profile and every unsupported construct with a `CompileError`, never a silent pass.
- **`SnapshotValidator`** is the `ProfileValidator` over a `ProfileSet`: cardinality, `fixed[x]`/`pattern[x]`, types, target profiles, extension definitions and contexts, profile invariants (with a `FhirPathEngine`), and slicing with the `value`, `pattern`, `exists`, `type` and `profile` discriminators and the `closed`, `open`, `openAtEnd` and `ordered` rules.
- **`skeleton(type)`** builds a minimal instance of any resource type that passes tiers 1 and 2, for tests and tooling.

## Tests

- `tests/structure.rs` covers each rule, with expected locations, plus skeletons of every type.
- With `HEALTH_FHIR_R5_EXAMPLES` set, it also runs the whole official corpus: every example must pass tier 1 and then parse into the typed model, apart from `KNOWN_UNPARSEABLE_EXAMPLES`.
- `tests/invariants.rs` covers:
  - violated and holding invariants;
  - the decimal conformance suite: scale, 28 digits, `-0`, exponents, decimal arithmetic, `~`, UCUM `=`, and 29-digit fail-closed;
  - non-ASCII units, silenced traces, and skeletons of every type;
  - with `HEALTH_FHIR_R5_EXAMPLES` set, the whole corpus, where each remaining failure must be confirmed by an independent check.
- `tests/profiles.rs` covers tier 3:
  - the official vital-signs, heart-rate and BP profiles (`tests/fixtures/profiles/`) on the official examples, valid and with a missing category, a wrong LOINC code, a wrong fixed unit and a missing component;
  - custom profiles (`tests/fixtures/custom-profiles/`) for every slicing rule and discriminator, patterns, types, targets, extension values and contexts, and invariants;
  - compile refusals, including a differential-only profile;
  - with `HEALTH_FHIR_R5_EXAMPLES` set, every official example that claims one of the profiles.
- `tests/performance.rs` holds the budget (ADR 0053): with `HEALTH_FHIR_R5_EXAMPLES` set, in a release build, tiers 1–3 must take p95 ≤ 2 ms (or `HEALTH_VALIDATION_P95_MS`) over the official clinical examples, with the vital-signs profiles active.
- `tests/java_differential.rs` compares our verdicts with the HL7 Java validator's (`tools/fhir/java-differential.sh`; fhir-r5-model.md § The HL7 Java validator differential). `examples/differential_cases.rs` writes its cases.
- A unit test in `src/invariants.rs` evaluates every check that `HOLDS_BY_SHAPE` skips over the corpus, and each must hold.
