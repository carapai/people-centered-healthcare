# health-fhir-validation

Layer: **contracts**. FHIR R5 validation (ADR 0016; fhir-r5-model.md § Validation, § Tier 1 in code). Pure: no I/O, no model crate.

- **`validate_structure(json)` and `validate_value(&value)`** run tier 1 on raw JSON (ADR 0051). They report:
  - an unknown or abstract `resourceType`;
  - unknown elements;
  - cardinality and required elements;
  - primitive JSON types, regexes and integer ranges;
  - choice exclusivity;
  - empty objects, arrays and strings;
  - `null` and `_name` alignment.

  Each `Issue` has an OperationOutcome code and a FHIRPath location.
- **`data/r5-elements.json`** is generated by `tools/fhir-element-table` from `hl7.fhir.r5.core#5.0.0`. Never edit it by hand. `tools/fhir/check-element-table.sh` checks it for drift, and `--write` regenerates it.
- **`skeleton(type)`** builds a minimal valid instance of any resource type, for tests and tooling.

## Tests

- `tests/structure.rs` covers each rule, with expected locations, plus skeletons of every type.
- With `HEALTH_FHIR_R5_EXAMPLES` set, it also runs the whole official corpus: every example must pass tier 1 and then parse into the typed model, apart from `KNOWN_UNPARSEABLE_EXAMPLES`.
- `examples/time_corpus.rs` times tier 1 over a directory, against the p95 ≤ 2 ms budget for tiers 1–3 (ADR 0053).
