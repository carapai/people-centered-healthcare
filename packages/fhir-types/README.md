# @health/fhir-types

FHIR R5 resources and data types for the client, generated by `tools/codegen` from the R5 element table that the Rust validator uses (client-application.md § Types). `src/r5.ts` is generated: do not edit it. Run `bun run generate` in `tools/codegen`.

- One interface per concrete resource (`Patient`, with `resourceType: 'Patient'`) and data type, with every element flattened.
- Backbone elements are nested interfaces named by path (`PatientContact`, `QuestionnaireItem`).
- Choice elements are one optional property per type (`valueQuantity`, `valueString`). Primitives have their `_name` element.
- JSON numbers are `LosslessNumber` from `lossless-json`, as the client parses them; build them with `new LosslessNumber('1.50')`.
- `FhirResource`, `ResourceType`, `ResourceTypeMap` and `resourceTypes`.

`test/types.ts` is a type-level test: `bun run typecheck` fails if a valid resource stops compiling or an invalid one starts to.
